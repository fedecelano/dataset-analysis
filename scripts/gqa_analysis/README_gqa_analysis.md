# GQA Dataset Analysis

This directory contains read-only scripts for inspecting the **original** and **cleaned** GQA scene-graph datasets. The analyses cover annotation statistics, visual examples, bounding-box geometry, image/annotation consistency, and label-frequency distributions.

The scripts are intended to support dataset understanding and quality assessment before developing layer-wise linear probes. **They do not perform dataset cleaning, delete images, modify annotations, or train probing models.** The cleaning procedure is maintained separately.

## 1. Project layout

The scripts are expected to be located under `scripts/gqa_analysis/` in the following project structure:

```text
project_root/

│   ├── gqa/
│   │   ├── annotations/

│   │   └── images/
│   └── gqa_cleaned/

│       │   ├── train_sceneGraphs.json
│       │   └── val_sceneGraphs.json
│       ├── image_ids/
```

Output subdirectories are created by the relevant scripts as needed. Both dataset versions reference the original image directory, `data/gqa/images/`; the cleaned dataset stores scene-graph annotations and image-ID lists, not a separate image copy.

## 2. Requirements and execution

Run the commands from the project root (paths inside the scripts are derived from their file locations, so another working directory is also supported):

```powershell
python scripts/gqa_analysis/inspect_gqa.py --dataset original
python scripts/gqa_analysis/analyze_gqa_bboxes.py --dataset original
python scripts/gqa_analysis/check_gqa_images.py --dataset original
python scripts/gqa_analysis/visualize_gqa_scene_graphs.py --dataset original
python scripts/gqa_analysis/plot_frequencies.py --dataset original
```

To analyze the cleaned dataset, replace `original` with `cleaned`. The default value of `--dataset` is `original` for all five scripts.

The scripts use the Python standard library plus the following external packages:

| Package | Used by |
|---|---|
| `numpy` | Bounding-box analysis, frequency plots |
| `pandas` | Bounding-box analysis, frequency plots |
| `matplotlib` | Bounding-box plots, scene-graph visualization, frequency plots |
| `Pillow` (`PIL`) | Scene-graph visualization |

Install these dependencies in the project's Python environment if not already available:

```powershell
python -m pip install numpy pandas matplotlib Pillow
```

Python 3.10 or later is a suitable baseline for the revised scripts. This document does not pin package versions or define a reproducible environment lockfile.

**Execution order:** `plot_frequencies.py` requires the three frequency CSVs generated by `inspect_gqa.py` for the **same dataset version**. The other analysis scripts can run independently when their input files are present.

## 3. Scripts

### 3.1 `inspect_gqa.py` — Annotation statistics and vocabularies

**Purpose.** Computes descriptive statistics separately for the train and validation scene graphs: number of images, object instances, attribute occurrences, relation occurrences, vocabulary sizes, and label frequencies. It also compares vocabularies across splits.

**Input:** `data/gqa/annotations/{train,val}_sceneGraphs.json` or the corresponding files under `data/gqa_cleaned/annotations/`.

**Outputs** under `outputs/gqa_analysis/<dataset>/tables/`:

| File | Description |
|---|---|
| `dataset_summary.csv` | Image, object, attribute and relation totals, including unique label counts, by split |
| `vocabulary_overlap.csv` | Number of distinct labels in train and validation and the size of their intersection/differences |
| `vocabulary_differences.csv` | Labels found only in train or only in validation, with occurrence counts |
| `class_frequencies.csv` | Object-label counts in train and validation |
| `attribute_frequencies.csv` | Attribute-label counts in train and validation |
| `relation_frequencies.csv` | Relation-label counts in train and validation |

**Interpretation:** frequencies count *annotation occurrences*, not the number of different images containing a label. Strings are used as recorded in the scene graphs; this script does not normalize or merge synonymous labels. A relation occurrence is counted from an object's relation list.

### 3.2 `visualize_gqa_scene_graphs.py` — Contrasting qualitative examples

**Purpose.** Produces a structured qualitative comparison using four distinct images from **train** and four from **validation**.

Each split contributes one example for each profile:

- `simple`: comparatively low annotation density;
- `attributes`: comparatively attribute-rich;
- `relations`: comparatively relation-rich;
- `complex`: comparatively high combined annotation density.

Profiles are selected **relative to the eligible images of each split** using ranks/scores, rather than universal thresholds defining scene complexity. Selection uses stable ordering and does not require random sampling.

Candidate images must have **2–14 objects**, at most **36 attribute occurrences**, and at most **24 relation occurrences**, with a locally available image and relation targets resolvable within the scene graph. These limits keep all annotations in the visualization without truncating the tables. Consequently, the selected samples are illustrative, not statistically representative of all GQA images.

**Input:** selected version's train/validation scene graphs plus image files under `data/gqa/images/`.

**Outputs** under `outputs/gqa_analysis/<dataset>/qualitative_examples/`:

```text
overview.png
train_simple.png
train_attributes.png
train_relations.png
train_complex.png
val_simple.png
val_attributes.png
val_relations.png
val_complex.png
```

`overview.png` places the four train examples in the first row and the four validation examples in the second row. Each detailed PNG places the annotated image with numbered bounding boxes **above** tables of objects/attributes and instance-level relations. No separate `.txt` annotation files are generated. A fresh run produces nine PNGs; unrelated files already in the output directory are **not** deleted automatically.

### 3.3 `analyze_gqa_bboxes.py` — Bounding-box validity and size

**Purpose.** Examines every annotated object's bounding-box geometry without changing the underlying JSON annotations.

It uses three mutually exclusive states:

| State | Definition |
|---|---|
| `valid` | Finite coordinates and positive dimensions; positive image dimensions; box entirely inside the image |
| `clippable` | Finite coordinates and positive dimensions; box extends beyond one or more image boundaries but overlaps the image with **positive area** |
| `invalid` | Non-positive box dimensions, invalid/non-finite geometry, invalid image dimensions, or no positive-area overlap with the image |

Negative `x`/`y` values **do not automatically make a box invalid**. A partially visible box is `clippable`; a fully external box is `invalid`. **There is no 5% overflow threshold.** Clipping here is used to calculate the usable area, not to rewrite annotations.

For `valid` and `clippable` boxes, relative size is computed as:

```text
clipped box area / image area
```

The area is grouped into seven percentage ranges: `<0.1%`, `0.1–1%`, `1–5%`, `5–10%`, `10–25%`, `25–50%`, and `>50%` (upper intervals are implemented with left-inclusive bin edges).

**Outputs:**

- `tables/bbox_quality_summary.csv`: counts and percentages of `valid`, `clippable` and `invalid` relative to **all boxes** in each split;
- `tables/bbox_size_distribution.csv`: counts and percentages by clipped area **among valid and clippable boxes only**;
- `plots/bbox_size_distribution.png`: train/validation comparison of size distributions.

**Planned downstream step (not implemented here):** use these rules when revising the separate dataset-cleaning script to clip recoverable boxes and exclude invalid boxes, taking care of references to removed objects.

### 3.4 `check_gqa_images.py` — Image and split-ID integrity

**Purpose.** Cross-checks the image files stored under `data/gqa/images/` against image IDs in both scene-graph splits. It detects missing images, shared train/validation IDs, and multiple supported image files with the same stem. The cleaned-dataset mode also compares the scene graphs against `data/gqa_cleaned/image_ids/train.txt` and `val.txt`, checking missing/extra and repeated IDs.

Image lookup scans files directly within `data/gqa/images/`, accepting `.jpg`, `.jpeg`, and `.png` with case-insensitive extensions; it does not recursively search subdirectories or verify that image files can be decoded.

**Outputs** under `outputs/gqa_analysis/<dataset>/tables/`:

| File | Description |
|---|---|
| `image_integrity_summary.csv` | Metric/count pairs for image availability, scene-graph IDs, split overlap, duplicate image files, and (for cleaned data) consistency with ID lists |
| `image_integrity_issues.csv` | Individual findings with `issue_type`, `split`, `image_id`, and `details` |

A matching summary is also printed in the terminal. **An image without a train/validation scene graph is informational, not automatically erroneous**: the image collection can contain images for other GQA splits. The integrity summary concerns file/ID consistency; it does not validate bounding boxes, semantic labels, or the accuracy of annotations.

### 3.5 `plot_frequencies.py` — Label-frequency visualizations

**Purpose.** Uses the CSVs produced by `inspect_gqa.py` to generate two combined figures, each with panels for object classes, attributes and relations.

**Prerequisite:** for the selected dataset version, run `inspect_gqa.py` before this script.

**Outputs** under `outputs/gqa_analysis/<dataset>/plots/`:

| File | Description |
|---|---|
| `frequency_distributions_combined.png` | Independent train/validation rank-frequency curves (logarithmic frequency axis) |
| `top_labels_relative_combined.png` | Relative frequencies in train/validation for the top-N labels selected from train |

In the **rank-frequency** figure, each split is sorted *independently* by descending frequency; zero counts are omitted. Consequently, a given rank may refer to different labels in train and validation. The figure compares the *shapes* of the long-tail distributions, not label-by-label ranks.

In the **top-N** figure, labels are chosen according to their **training-set frequency** and then their percentages in both splits are compared. For each label type, a percentage is the count of that label divided by the total count of annotations of that type in the relevant split. The default is **30** labels; customize it with `--top-n`:

```powershell
python scripts/gqa_analysis/plot_frequencies.py --dataset cleaned --top-n 20
```

These relative frequencies are **not percentages of images**. When a split has no occurrences, the corresponding percentage is undefined; the plot displays an explanatory annotation rather than attempting to divide by zero.

## 4. Recommended analysis workflow

For each dataset version, the following order is convenient:

1. **Check availability and split correspondence:** `check_gqa_images.py`.
2. **Generate quantitative annotation tables:** `inspect_gqa.py`.
3. **Analyze box geometry:** `analyze_gqa_bboxes.py`.
4. **Inspect qualitative examples:** `visualize_gqa_scene_graphs.py`.
5. **Plot label-frequency distributions:** `plot_frequencies.py` (after step 2).

Repeat the workflow with `--dataset cleaned` to compare outputs with the original dataset. The two versions write to separate directories and therefore do not overwrite each other's results.

The current scripts intentionally do **not** generate a unified original-versus-cleaned comparison report; such comparisons can be made from the corresponding CSVs and PNGs.

## 5. Interpretation and limitations

- **Dataset versions:** “original” and “cleaned” refer to the two sets of scene-graph annotation files. Both rely on the same physical image directory.
- **Data cleaning:** these analyses are read-only. The current cleaned annotations must not be interpreted as already having undergone the *planned* bounding-box clipping and removal step unless that has been performed separately and verified.
- **Sampling:** the eight qualitative images deliberately contrast annotation densities; they are not a random or unbiased sample.
- **Annotation frequencies:** object, attribute and relation counts refer to recorded occurrences. They should not be interpreted as per-image label prevalences.
- **Bounding-box usability:** geometric validity is necessary for spatial analysis, but does not establish semantic correctness or annotation completeness.
- **Data integrity:** matching IDs and image files do not establish that images are readable, that all scene-graph references are valid, or that labels are correct.
- **Linear probing:** this folder contains preparatory dataset analyses, not probing training, data splits for probes, attention-map analysis, or layer-wise visual feature extraction.
- **Source preservation:** do not remove images without train/validation scene graphs from the source image collection merely because they are not used by the current probing subset.

## 6. Reproducibility notes

- The analyzed dataset version is chosen explicitly with `--dataset` (or defaults to `original`).
- All five scripts derive project paths from their location, rather than the terminal's current directory.
- The qualitative selector uses deterministic candidate ordering and stable tie-breaks; a change to the underlying annotation data may still change which examples it selects.
- Generated files can be overwritten by later runs with the same parameters. Keep experiment-specific copies or record configurations if outputs need to be archived.
- When figures or tables are used in thesis writing, record the input dataset version, script version, run parameters, and any preprocessing changes applied before analysis.
